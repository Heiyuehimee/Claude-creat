# PDF 漫画阅读器 · 需求说明（v1）

> 状态：草稿，待确认
> 平台：仅安卓手机（竖屏为主）
> 技术：Flutter
> 交付方式：一次做完再交付 APK（开发过程中由我自行分阶段测试）

---

## 0. 原则

- **完全离线可用**，不联网、不上传任何数据。
- **默认不移动、不改名、不修改漫画原文件**。所有整理结果只存在 App 自己的数据库里。
- **人工结果优先级高于自动识别**。重新扫描绝不覆盖用户确认或锁定过的内容。
- 重新扫描**不能丢失阅读记录和人工整理结果**。

## 1. 文件来源与扫描

### 1.1 支持格式
| 格式 | v1 |
|---|---|
| PDF | ✅ |
| 图片文件夹（jpg / jpeg / png / webp / gif 首帧 / bmp） | ✅ |
| ZIP / CBZ / RAR / 7z 等压缩包 | ❌ 不支持 |

### 1.2 目录授权
- 使用**安卓系统文件夹选择器**授权一个或多个漫画根目录，授权在重启后保持有效。
- 可以添加、移除根目录。

### 1.3 扫描
- 自动递归扫描已授权的目录。
- **展示扫描进度**（已扫描文件数 / 当前目录）和**扫描结果**（新增、删除、移动、修改各多少个，以及进入"待确认"的数量）。
- 扫描在后台进行，不阻塞书架浏览和阅读。

### 1.4 文件变化检测
安卓上没有可靠的实时文件监听，因此按以下方式实现：
- **打开 App 时**自动做一次增量扫描。
- **书架下拉刷新**时手动触发增量扫描。
- 识别以下变化：
  - **新增**：新文件或新文件夹进入识别流程。
  - **删除**：标记为"文件丢失"，**保留**阅读记录和整理结果（文件找回后自动恢复）；用户可以手动清理。
  - **移动 / 改名**：根据文件大小和内容指纹认出是同一本，迁移阅读记录和整理结果。
  - **修改**：重新生成封面和页数，保留阅读记录。

## 2. 封面书架（主界面）

主界面是漫画书架，不是文件管理器。

### 2.1 每个系列卡片显示
- 封面
- 系列名称
- 作者或社团
- 章节数量
- 阅读进度（如 `12 / 30 话`，或进度条）
- 最近阅读状态（如"3 天前读过"）
- 未读标记（有新章节或从未读过）

### 2.2 交互
- 一屏能看到较多漫画；**可以调整封面大小（显示密度）**，如每行 3 / 4 / 5 列。
- 封面**逐步加载**，不能等全部封面生成完才显示界面。
- 已生成的封面**缓存到本地**。
- 书架顶部有"**继续阅读**"入口，一键回到最近读的漫画。
- 系列数量很多时（目标：**3000 个系列**）依然可以流畅滚动。

### 2.3 系列详情页
- 系列信息（封面、名称、作者 / 社团、章节数、阅读进度）。
- 章节列表：按章节顺序排列，显示每话的阅读进度和已读 / 未读状态。
- 在这里可以对系列和章节做手动整理（见第 4 节）。

## 3. 系列与章节自动识别

### 3.1 目标结构
```
系列
├── 第 1 话
├── 第 2 话
├── 第 2.5 话
├── 番外
└── 总集篇
```

### 3.2 识别依据
- 文件名
- 父目录名
- 作者或社团（如 `[社团名 (作者名)]` 这种格式）
- 标题中重复出现的核心词
- 章节标记：卷、话、篇、回、章、枚目、Vol、Ch、#
- 上中下、前后篇
- 番外、Side、总集篇、合集
- **噪音信息要剔除**：汉化组、活动编号（如 C102、COMIC1☆22）、`[DL版]`、`[中国翻訳]`、`[無修正]`、扫图组标记等
- 数字：罗马数字（Ⅰ、Ⅱ、IV）、阿拉伯数字、全角数字、中文数字（一、二、十二、廿）、小数话（2.5）

### 3.2.1 文件夹角色判断
父目录不一定是系列名，扫描时先判断每个文件夹的角色：
| 角色 | 特征 | 例子 | 处理 |
|---|---|---|---|
| **分类目录** | 子项标题彼此无关 | `A级`、`已审核\附身`、`D级无价值\换身` | 只作为目录筛选条件，不参与系列命名 |
| **系列目录** | 子项共享核心标题，或文件名只有编号 / 缩写 | `龙王的工作\龙王的工作1.pdf`、`kaba\怪异情侣\1.pdf`、`kaba\溺爱\na2.pdf` | 文件夹名作为系列名 |
| **包装目录** | 只包含一个同名 PDF | `伊人酒吧1\伊人酒吧1.pdf` | 当作那个 PDF 本身，不算一层 |
| **图片漫画** | 直接包含图片 | 各类图片文件夹 | 一个文件夹 = 一话 / 一本 |

- 判断拿不准时按"分类目录"处理，避免把无关作品合并。
- 用户可以在人工整理里手动改文件夹角色，修改后会记住。

### 3.3 置信度机制
不做"模糊匹配后强制合并"。
| 置信度 | 处理方式 |
|---|---|
| 高 | 自动归入同一系列 |
| 中 | 放进"**待确认**"，由用户确认或修改 |
| 低 | 保持为独立漫画 |

- 用户确认或修改后**永久记住**，以后重新扫描时沿用。
- "待确认"列表里显示建议的合并方案及理由（例如"核心词相同 + 同作者 + 章节编号连续"），可以一键接受或拒绝。

### 3.4 从真实库中归纳的识别规则
测试集：`test/fixtures/real_library_paths.txt`（约 590 个 PDF + 约 300 个图片文件夹）。

| 情况 | 例子 | 期望结果 |
|---|---|---|
| 文件名只有编号或缩写 | `怪异情侣\1.pdf … 10.pdf, ql11.pdf … ql14.pdf` | 系列"怪异情侣"，第 1～14 话 |
| 无编号视为第 1 话 | `溺爱\na.pdf, na2.pdf … na10.pdf` | `na` = 第 1 话 |
| 缩写 + 小数 + 特殊后缀 | `痴迷\cm.pdf, cm2 … cm5, cm5.5, cm c.pdf` | 按 1、2…5、5.5 排序；`cm c` 无法判断编号，排在末尾，标记为待确认 |
| 上下篇和数字编号混用 | `媽媽的味道-上 / -下 / 03 / 04` | 上 = 1，下 = 2，然后是 3、4 |
| 版本号式编号 | `君になる1.0 / 1.5 / 2.0 / 2.1 / 3.0` | 按数值排序 |
| 副标题篇章 | `君になる～美遊編～`、`君になる総集編` | 归入同一系列，排在编号话之后（总集篇放最后） |
| 一个文件包含多话 | `改変対象 第1-4話`、`染指 1-4`、`我的寄生兽妈妈1-2` | 一个章节，标题显示为"第 1-4 话"，按起始话排序 |
| 主编号 + 附加编号 | `他人になるクスリ5 +5.2`、`7 + 7.2` | 编号取 5 / 7 |
| 分支版本 | `邻家的天使大人4（好分支）` | 与第 4 话并列，排在第 4 话之后 |
| 中间编号缺失 | `主管的秘密01, 03, 04, 05, 主管的秘密2(手繪)` | 正常排序为 1、2、3、4、5，`(手繪)` 视为备注 |
| 同一社团的不同写法 | `[Senpenbankashiki (DATE)]`、`[千変万化式 (DATE)]`、`(DATE)]` | 作者都识别为 DATE；社团别名作为匹配依据之一 |
| **同一作者的不同作品** | `(谷口さん)` 名下的 `君になる`、`かしマシ`、`リモート憑依` 等 | **不能**因为作者相同而合并，必须核心标题相同 |
| 同一系列分散在不同目录 | `他人になるクスリ4` 在 `A+`，`7` 在 `已审核\附身` | 可以跨目录合并（高置信度），目录筛选时按章节所在目录分别命中 |
| 副标题不同、主标题 + 编号连续 | `ゆうたいの魔法陣 / 2 / 3 ～副标题～` | 合并 |
| 双语标题 | `Nikutai Dorobou no Udewa 窈取肉體的手鐲` | 保留原样作为标题，两种文字都能被搜到 |
| 需要剔除的噪音 | `[中国翻訳]`、`[DL版]`、`[Chinese]`、`[Digital]`、`[xx汉化组]`、`【xx个人汉化】`、`(C92)`、`(#にじそうさく4)`、`(COMIC xx 2019-08)`、`(コミックアンリアル 2020年2月号 Vol.83)`、`[ページ欠落]`、`(12P)`、`[AI_Generated]`、`_-_E-Hentai_Galleries.3833902`、`(chinese)`、`（中国語版）` | 不参与系列匹配，但保留在原始文件名里供搜索 |
| 原作名括号 | `(FateGrand Order)`、`(アズールレーン)`、`(艦隊これくしょん -艦これ-)` | 识别为"原作"字段，不参与系列匹配 |
| 文件名残缺 | `(DATE)] 他人になるクスリ5` | 容错解析，不能报错 |
| 下划线代替空格 | `[RAIN]_桃绿色的圆舞曲_[AI_Generated]` | 下划线按空格处理 |
| 空文件夹 | `kaba\20` | 忽略 |

### 3.5 识别质量验收
- 测试集上要求：**错误合并 = 0**（宁可放进待确认，也不能合错）；上表中所有例子的结果和期望一致。

### 3.6 重复内容
- `已审核`、`D级无价值` 里和 PDF 同名的图片文件夹是筛选后留下的废料，**不做特殊处理**。你不会把它们复制到手机上；如果复制了，可以用"忽略文件夹"排除。

## 4. 人工整理

用户可以：
- 修改系列名称
- 修改作者或社团
- 修改章节名称
- 修改章节编号和顺序（支持拖动排序）
- 把章节移动到另一个系列
- 合并两个系列
- 拆分错误合并的系列
- 选择或更换系列封面（从任意一页中选）
- 忽略某个文件或文件夹（以后扫描时跳过，可以在设置里恢复）
- 锁定人工结果，重新扫描后不被自动规则覆盖

规则：**所有人工修改默认就是锁定的**；人工结果优先于自动识别。

## 5. 搜索、筛选、排序

### 5.1 搜索范围
系列名、漫画标题、章节名、作者或社团、原始文件名、文件夹名称。

### 5.2 搜索语法
| 写法 | 含义 |
|---|---|
| `关键词A 关键词B` | 同时匹配（AND） |
| `关键词A \| 关键词B` | 任意一个匹配（OR） |
| `-关键词` | 排除 |

- 支持中文、日文、英文；不区分大小写和全角 / 半角。
- 输入时**即时显示结果**。

### 5.3 筛选
全部漫画、最近阅读、未读、已读、待确认、PDF 漫画、图片漫画、按目录（如 `A级`、`已审核\附身`，选上级目录时包含它的子目录）、自定义分类。

### 5.4 排序
名称、最近阅读、最近添加、章节数量、阅读进度。正序、倒序都支持。

### 5.5 自定义分类
- 可以新建分类，把系列放进去；一个系列可以属于多个分类。

## 6. 阅读器

### 6.1 翻页
- 左右翻页，**可以切换方向**：从左往右（普通）、从右往左（日漫）。
- 可以按系列分别记住翻页方向。
- **点击屏幕左右区域翻页**，点击中间呼出菜单。
- **音量键翻页**（可开关）。

### 6.2 查看
- 双指缩放、双击放大，放大后可以拖动查看。
- 页码拖动条 + 缩略图跳页。

### 6.3 连续阅读
- 一话读完**自动进入下一话**（翻过最后一页时提示"下一话：xxx"，再翻一次进入）。

### 6.4 进度
- 自动记住每话读到第几页，下次打开直接回到这一页。
- 读到最后一页时标记为已读。
- 系列进度根据各章节的已读情况统计。

### 6.5 性能
- 预加载前后几页，翻页不出现白屏等待。
- 大 PDF（500 页以上，或 300MB 以上）也能正常打开和翻页。

## 7. 不在 v1 范围内

- 压缩包格式（ZIP / CBZ / RAR / 7z）
- Windows 版本、平板双页并排、墨水屏优化
- 上下连续滚动（条漫模式）
- 云同步、联网获取元数据
- 修改原文件（改名、移动）

## 8. 交付与验收

- **交付物**：GitHub Releases 里的 APK 安装包，以及源码。
- **由我自行完成的检测**：
  - 识别规则单元测试（基于你提供的文件名样本）
  - 数据库迁移和"重新扫描不丢记录"的测试
  - 在 GitHub Actions 的安卓模拟器里跑核心流程：授权目录 → 扫描 → 书架 → 阅读 → 进度保存，并截图检查
- **由你验收**：在手机上用真实漫画目录试用，反馈手感和识别结果。
